### 3.1 The model layer: one endpoint for every agent

- **What.** `server/llm.ts` is rebuilt on `openAiChat` from `server/agentSearch.ts`: any OpenAI-compatible chat completions endpoint with tool calling, chosen by `LYCEUM_AGENT_PROVIDER` (openai, openrouter, gemini, groq, ollama, custom), `LYCEUM_AGENT_BASE_URL`, `LYCEUM_AGENT_MODEL` and `LYCEUM_AGENT_API_KEY`, read from `.env` on every request. `ANTHROPIC_API_KEY`, `LYCEUM_MODEL` and `@anthropic-ai/sdk` are gone. Intake reads the tool call or JSON in the reply; the free-text agents (authoring, evaluator, analogy, signal) answer in one chunk instead of streaming (the code marks this "ponytail", the teammate's word for a known limit). `/api/health` now reports `live` when the `LYCEUM_AGENT_*` lines are set. The fixtures still answer when no model is set.
- **Checks.** `src/prove-agent-search.ts` gains a check on intake's tool call, text JSON, a wrong tool, no JSON and the free-text agents.
- **Rules.** No number moves; the fixtures and the deterministic paths are unchanged. What goes stale: `.env.example` and the documents that describe "an Anthropic key" (`docs/lyceum-pitch-plan.md` line 52, DECISIONS.md's 22 October entry, `docs/as-built.md`). The pull request says Claude still works through `custom` with the base URL `https://api.anthropic.com/v1`; that is to be verified with one call before anything says it.
- **Verdict.** Take. Add `anthropic` as a named provider in `MODEL_PROVIDERS` (its base URL, needs a key) once the one call confirms it, so the documented path survives as one line in `.env`. Keep the one-chunk reply and say so in the Settings guide's limitation, or restore token streaming in `openAiChat` (`stream: true`), which is a few lines; the owner's call (Decision 3).

### 3.2 Agent web search and the Settings page

- **What.** `server/agentSearch.ts`: a tool-calling loop with four tools, `web_search`, `web_fetch`, `collect_board` (the existing Greenhouse and Lever collector) and `save_posting`; the model chooses what to read and keep, and a kept posting's text is the page as fetched or the board's listing, never the model's words. `server/webTools.ts`: a search chain in the order set in `.env` (SearXNG, then DuckDuckGo's HTML results page by default; Tavily, Brave, Serper and Google Programmable Search with keys), a guarded fetch (public addresses only, every redirect re-checked, 3 MB and 20 seconds), and a schema.org `JobPosting` reader. `src/lib/agentSettings.ts` and `src/ui/screens/Settings.tsx`: the settings as the API read them, keys shown as their last four characters, a test for the model (it must call a tool) and for the search. `agent` joins `SOURCE_POLICIES` in `src/lib/collect.ts` with a policy that says many sites forbid automated reading. The run streams its steps into the collection log. `searxng/settings.yml` and the `searxng` service in `docker-compose.yml`. Watch's default source changed from the saved sample to the agent. A Settings item joins the shared navigation for every persona.

## 6. How to take it: the mechanics

- **One `take`, not ten.** The branches are cumulative and all are 0 behind `team/main`, so `node scripts/team.mjs review feat/prism-slide-content` (the full diff goes to a temp file; Section 3 is the reading of it) and `node scripts/team.mjs take feat/prism-slide-content` cover everything. - **Commit the 24 October tree first** (T0), so the take lands on a clean tree, the diff of the take is the take alone, and the backup is small.
